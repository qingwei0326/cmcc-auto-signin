Token 管理

从 HAR 一次性导入 qwhdhub 与 BASS 的登录凭证

HAR 导入 一份 HAR 同时更新 qwhdhub 与 BASS

手机抓包（Stream / ProxyPin）导出含 appTokenLogin 或 wap.fj.10086.cn 请求的 HAR。 qwhdhub token 按 HAR 里的手机号自动归位；BASS token 跟随同一号码写进 configs_fj。
导入后回「总览」点右上角「刷新状态」即可复核 token 是否生效。 抓包文件在微信里也能直接用：点「自动查找」会连微信接收目录一起扫， 不用先把文件挪到项目目录。

优惠专区抽奖 自动从最新 HAR 取 token，刷任务 + 抽奖

先打开一次「优惠专区抽奖」页面，让抓包工具记录，然后在下面点执行—— 脚本会自动在项目目录 / 下载 / 微信接收目录里找最新的 HAR 并提取 token。 抓到的 bearer 能撑数小时，不必每次都抓。token 失效会提示重新打开活动页。

秒杀抢券

cmcc_seckill.py · 签到有礼「每周秒杀」每天 12:00 抢 1 元话费券

执行秒杀

留空则由脚本按 secConfig 自动选场次
流程：校服务器时间 → 拉场次 → 查当日签到资格 → 等到点 → 密集重试 redeem。 开抢时会提前 0.4 秒出手以抵消网络延迟，被拒后每 2 秒核对一次库存，没货立刻停手。 抢到的券进 App「我的奖品」核销，脚本会推送到手机。
只需要提前几分钟准备——会话刷新 11:54 执行，秒杀 11:55 启动。 如果启动时会话未就绪，脚本会每 15 秒重试并重新读取配置； 等待期间重新导入 HAR 也能被自动识别，不会在启动时直接退出。

票据寿命由计划任务 MobileTokenLifeProbe 每 2 分钟探测一次 （每账号只发一次登录请求，确认失效后自动停手）。 签发时刻取自 HAR 里 appTokenLogin 的时间戳， 所以结论能精确到分钟，而不是「大概半小时」。
每次 qwhdhub 签到成功后，会自动保存该账号的活动会话 cookie （gui_data/seckill_session_<尾号>.json）。实测仅凭该 cookie 就能调用秒杀接口， 完全不需要 app_token。
会话只能活 2 小时（实测：04:22 建立 → 06:22 服务端返回 GOTO_LOGIN 准时失效），所以刷新时刻必须紧邻开抢，不能靠早上那次签到。 若 app_token 也已过期，请在开抢前抓包导入。

拓展活动

cmcc_extra.py：周六游戏中心 / 追剧领福利 / 玩游戏抽话费

执行拓展活动

三个活动各有自己的消耗窗口，脚本自己判定，不在窗口就只报余额、不消耗：
· 周六游戏中心：游戏币攒着，周六 12:00 起才能抽（余额按 31 天周期清零）
· 追剧领福利：抽奖次数只在周日开放
· 玩游戏抽话费：每周一刷新的周任务，没有抽奖
计划任务 MobileGames 默认每天 12:05 跑一次，正好覆盖周六 12:00 的游戏币抽奖， 其它日子只报状态、不消耗。
拓展活动需要有效 app_token（约 30~46 分钟寿命）。 票据过期时三个活动一个都跑不了，需要重新抓包导入。

定时任务

Windows 计划任务注册 / 注销（PowerShell Register-ScheduledTask）

Windows 计划任务

推荐方案：签到 08:30 · 每日奖励 06:00 起每小时 · 会话保活每 90 分钟 · 会话刷新 11:54 · 秒杀 11:55 · 拓展活动 12:05 · 票据探测每 2 分钟。 一键配置会把这 7 个任务按上面的时刻一次注册好，覆盖当前触发时间； 想单独调某一个，改下面表格里的「触发时刻」再点该行的注册即可。
每日奖励三档（150/250/350）之间必须间隔 60 分钟，一次跑只能领一档。 这个任务从设定时间起每小时检查一次、共 17 次，能领就领，领完自动空转。
会话保活：每 90 分钟只试登录一次（--login-only，不签到、不推送）。 实测 jwtToken 单独用服务端不认，登录终究依赖 app_token（约 30 分钟寿命）， 所以保活续不了命：它只是在票据有效期内多跑几次，一旦失败就说明该重新抓包了， 每次结果记在 logs\keepalive.log。
票据寿命探测：每 2 分钟探一次 app_token 登录，签发时刻取自 HAR， 所以「票据到底活多久」能精确到分钟；确认失效后自动停手不再空转。
logs\ 下 daily / daily_reward / keepalive / session_refresh / seckill / games / token_life， 各任务的详细输出都在那里；「日志」页只显示本控制台发起的运行
